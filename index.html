科研 Agent 平台与端到端研究系统

这一类包含两种关键形态：科研 Agent 工作台（如 Claude Science、LatchBio、Conspecta、Benchling、FutureOS）为计算生物学、生物信息与湿实验研究者提供人机协作环境，深度串联本地/集群代码执行（Python/R/HPC）、科学数据库、实验记录（ELN）与 Provenance 溯源自纠；全自主科研闭环与端到端流水线（如 The AI Scientist、PaperQA2 / Falcon 生物智能体、DeepScientist、Spark-to-Paper、ARIS）则尝试实现从文献挖掘、Idea 构思到实验运行与论文生成的全自主闭环。自动化程度与把关机制各有侧重，需明确责任边界与人工审查机制。

关于自动化的“度”：成本口径（如“$10/篇”）是作者公布的典型值；可复现不等于真实，自动流水线可能产出有说服力但错误的结论；平台型产品要区分「模型能力」与「产品功能」（如 Claude Science 底层仍是现有 Claude 模型，新增的是科学渲染、数据库与计算集成）；自动或半自动内容应被视为初稿，责任仍在研究者。

一个负责任的科研自动化使用顺序

  1. 先明确你要的是“辅助检索/写作”还是“自动出稿”：前者风险低，后者必须有人工审查。
  2. 选择与你既有工具链（编辑器、模型、文献库、统计软件）兼容的方案，而不是追最新的。
  3. 审查 Skills / 脚本来源，只装可信、活跃维护的内容。
  4. 对自动产出的引用、数据与结论做人工核验，保留中间步骤与可复现记录。
  5. 投稿或申报前，确认期刊 / 机构 / 基金对 AI 使用与署名的规定。
  6. 把成本（API 费用、时间、出错返工）计入真实收益后再扩大使用范围。
