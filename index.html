通用 Work / Desktop Agent

国内代表产品

Work Agent 的核心不是“什么都能聊”，而是能处理本地文件、网页、数据和办公流程，并交付文档、表格、演示稿、应用或已完成的操作。国内产品常进一步结合本地桌面、即时通信和云端任务入口。

选型速查

先根据工作对象、执行位置和期望交付物缩小产品类别，再比较权限、可靠性、成本与人工接管能力。下表把常见目标映射到优先考察的类别和关键问题。

目标优先考察的类别关键问题
在当前项目里边看边改AI IDE / CLI Agent大仓理解、测试、权限、diff、撤销
把 Issue 委派出去，回来审 PRCloud / Repository-native Agent沙箱、并发、PR 质量、日志、凭据、成本
自动审查每个 Pull RequestRepository-native Review Agent全仓上下文、误报、规则、修复闭环、数据范围
处理本地文档、表格和 PPTWork / Desktop Agent文件保真、隐私、可撤销性、交付质量
自动填写网页或跨应用操作Browser / Computer Use登录态隔离、确认、失败恢复、提示注入防护
让个人 Agent 定时或常驻工作Personal / Always-on Agent设备在线、远程入口、记忆、密钥、预算、审计
开发自己的 Agent 或工作流Framework / Workflow PlatformRuntime、状态、工具、部署、观测、人工介入、许可证
给多个 Agent 统一购买模型额度Coding / Token Plan 或 Router客户端白名单、模型、速率、真实成本、数据条款
生产级模型托管与企业治理Inference / Hyperscaler Platform区域、SLA、网络、合规、专用部署、可观测性
  1. 先确定工作对象：代码、仓库、网页、桌面还是办公文件。
  2. 再确定执行位置：本机、云沙箱、CI 还是常驻服务器。
  3. 选择 Harness / 产品入口。
  4. 最后比较模型和额度方案。
  5. 用真实任务测试成功率、人工接管、回滚与总成本，而不是只看模型榜单。
